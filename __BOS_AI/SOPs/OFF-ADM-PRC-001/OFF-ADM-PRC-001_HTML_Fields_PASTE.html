ℹ Why This SOP Exists

Material prices in BOS feed every estimate and every work order materials list. The supplier price import reads a supplier's catalog file, matches each line to our materials, shows a dry-run report of what would change, and writes the catalog only when the office approves. Lines it cannot match wait in two queues for a person to decide. This SOP exists so an approval is a read decision, not a reflex; so a large price jump is held for review rather than applied; and so unmatched lines are resolved without creating duplicate materials. The pipeline is built and live but has not yet been run against a full real supplier catalog — the first runs follow the extra rails in this SOP.

field_sop_responsibilities

MUST
  • The office manager must read the dry-run report before approving: the match summary by tier, the price-change impact, and the sample rows. Approve is a decision about those numbers.
  • The first production run of any supplier must be a small file (20–30 rows) agreed with Todd, after a database snapshot, with the same file run in the development copy first. Only after it checks out does a full catalog run.
  • After every commit the office manager must spot-check: open a handful of the auto-applied materials, confirm the supplier link price and the price-history line "Updated from ingest batch #N", then review the items the commit held in Price Review.
  • Rows in the Fuzzy Match Review must be confirmed only when the proposed material is the same product in the same unit of measure; anything else is Override or Send to Discovery.
  • Rows in the Discovery Queue must be linked to an existing material when one exists. Create New Material only after searching, and never for a discontinued product — use Mark as Replacement.
  • A rejected batch or row must carry the reason in its notes. Reject Batch cannot be undone.
MUST NOT
  • Do not approve a batch whose report shows errors or an unexpected number of "requires review" or discovery rows without asking why. A supplier changed a column, or the wrong file was uploaded.
  • Do not upload the same file twice "to be sure". There is no duplicate guard; a second upload is a second batch to reject.
  • Do not create a new material for a line whose description matches an existing one in a different pack size — link it, so the pack tiers stay on one record.
  • Do not expect an undo. Committed prices are written to the supplier links and the price history; corrections are made forward, by hand or by the next import.

field_sop_steps — Steps & Procedures

field_sop_steps

Overview

1. UploadUpload Catalog → supplier, file → Upload + parse.
2. Dry runBatch page: match summary, price impact, samples.
3. ApproveApprove and Commit — or Reject Batch.
4. VerifySpot-check materials, price history, Price Review.
5. QueuesFuzzy Match Review, then Discovery Queue — Resolve each row.

Pre-Checks

  • The file is from the supplier you will select, in the format their configuration expects.
  • Nothing is pending in Price Review from a previous batch (or you know what is).
  • First run only: snapshot taken, development run reviewed, Todd aware.

Steps

1UploadOffice manager
  • Admin ▸ Materials ▸ Supplier Price Ingest ▸ Upload Catalog (/admin/materials/supplier-ingest/upload). Choose the Supplier (only suppliers with an active configuration are listed), the Source file, add Notes (where the file came from, which run this is). Press Upload + parse.
  • The batch opens at Pending Dry Run and refreshes itself until the dry run is complete. Nothing has been written to the catalog.
2Read the dry-run reportOffice manager
  • Match summary: Tier 1 (manufacturer + item number), Tier 2 (known supplier SKU) and Tier 3 high (strong description match) say ✓ will auto-apply. Tier 3 medium and ambiguous Tier 1 say ⚠ requires review. Discovery rows route to discovery queue. Skipped rows (discontinued, excluded bundle, do-not-use) take no action. Errors are listed — an unrecognized unit of measure is the usual one.
  • Price change impact (auto-apply rows only): new supplier links to create; existing links changing within ±10% — will apply; increases of 10% or more — held for Price Review. If the report says the impact took too long, use Export Detailed Report (CSV).
  • Sample rows per tier (up to 10) and the discovery breakdown by inferred bundle. Open a few samples: is the match the same product?
3Approve or rejectOffice manager
  • Report as expected: press Approve and Commit. The confirmation names the counts and warns that a batch of 500 rows or more runs on a progress page — stay on it. On commit BOS, per auto-apply row: creates the supplier link if none exists, or updates the link's unit cost, effective date (today), source and notes; fills the supplier SKU if it was empty; writes a price-history line naming the batch; holds any increase of 10% or more in Price Review instead of applying it; and recomputes the material's cost. Decreases always apply.
  • Wrong file, wrong supplier, or a report you do not understand: press Reject Batch and write why in the batch notes. It marks the batch and every row rejected, writes nothing, keeps the batch for audit, and cannot be undone.
4Verify the commitOffice manager
  • The committed batch shows a banner with the pending counts for both queues. Open five to twenty of the auto-applied materials: the supplier link shows the new cost and today's date; the price history shows "Updated from ingest batch #N".
  • Admin ▸ Materials ▸ Price Review (/admin/materials/price-review): each held increase of 10% or more. Accept or reject each one on its merits — a real list-price rise versus a pack-size or unit error.
  • First production run: watch estimates and material lists for 48 hours; report anything odd to Todd.
5Fuzzy Match ReviewOffice manager
  • Supplier Price Ingest ▸ Fuzzy Match Review: rows the matcher scored medium (70–89), Tier 1.5 substring matches, and ambiguous matches with several candidates, highest confidence first. Filter by batch.
  • Open a row with Resolve →. Choose Confirm proposed match (commits that row now), Override — link to a different material, Send to Discovery Queue, or Reject row. Confirming a discontinued material is blocked. Save and load next row moves on; Ctrl/Cmd+Enter submits, Esc returns to the queue.
6Discovery QueueOffice manager
  • Supplier Price Ingest ▸ Discovery Queue: rows with no match, each with a note naming the best candidate. Filter by batch, description or inferred bundle.
  • Resolve → each row: Link to Existing Material (search first — same product, any pack size); Create New Material (bundle is pre-filled from inference; give it the title, manufacturer item number, manufacturer and unit) only when nothing exists; Mark as Replacement when the line replaces a discontinued material (pick the discontinued one, then an existing or new replacement); Reject row with notes for lines we do not stock.
  • Bulk Reject exists on both queues for a run of lines we will never carry. There is no bulk create or link.

✕ Reject Batch and committed prices cannot be undone

Reject marks every row rejected and is final. A commit writes supplier links and price history with no rollback button. Read before you press, and run a new supplier small and in development first.

⚠ Not yet a routine

The pipeline has been dry-run on partial scrapes in development but never on a full real catalog in production. Until the first full run has been verified, every run is a supervised run: small file, snapshot, development first, 48-hour watch.

ℹ What the dry run counts versus what the commit does

The dry run counts price drops of more than 10% among "will queue"; the commit applies all decreases and holds only increases of 10% or more. If the Price Review list is shorter than the report suggested, that is why.

Quality Checks

  • Every approved batch has a dry-run report that was read, and notes saying who ran it and why.
  • Spot-checked materials show the new supplier-link cost and a price-history line naming the batch.
  • Price Review is empty, or every held item has a decision, within two working days of a commit.
  • Both queues are empty for the batch within a week; no new material was created where one already existed.

Completion

  • Batch Committed; verification done; Price Review cleared; queues resolved.
  • Notes on the batch: file source, run number, anything odd and what was done about it.

Do / Don't

✕ Don't✓ Do
Approve because the dry run finished without errorsRead the tier counts, the price impact and the samples first
Upload again when the page is slowWait — Pending Dry Run refreshes itself; a second upload is a second batch
Create a new material for "PVC 3/4 in, case of 50"Link it to the existing 3/4 in PVC material
Confirm a fuzzy match because the words look closeSame product, same unit, or Override / Discovery
