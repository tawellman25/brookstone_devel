ℹ Why This SOP Exists

Customers ask for work through the website — the winterizing list, the fall cleanup page, the contact and holiday-lights forms — and the win-back callers create requests from the call list. Each request is a record of what the customer asked for; it is never the work itself. This SOP exists so every request is turned into a work order through the one button that does it properly: Approve & Create WO creates the work order for the matched property, links it back to the request and marks the request Converted in one step. A work order created any other way leaves the request open and unlinked, the customer appears unanswered, and the office later cannot tell which job answered which request.

field_sop_responsibilities — Rules & Responsibilities

field_sop_responsibilities
Switch to Source view in the CKEditor toolbar, then paste.
MUST
  • A request that should become a job must be converted with Approve & Create WO — never by creating the work order from the property page. The button creates the work order, links it to the request and marks the request Converted together.
  • The office must work the queue on its default filter — New and Needs Review — at least daily in season.
  • A request with no matched property must get one before approval: use Create Customer & Property when the person is new, or attach the existing property when the match was missed.
  • Every request the office closes without a job must be closed with the matching action: Mark Already Covered when a work order or contract already covers it, Mark Duplicate when another request is active, Reject (with the reason) otherwise. Rejection reasons are required and saved to the office notes.
  • What the customer typed must be treated as evidence, not truth: the property match, the eligibility result and the review flags on the card are what BOS verified.
  • Review flags (contract already completed for the year, supply mismatch, ZIP out of area, snow contract requested…) must be read before approving. They never block the button; they tell you what to check.
MUST NOT
  • Do not create the work order by hand and then try to mark the request Converted — BOS refuses: a request cannot be Converted without a linked work order.
  • Do not approve a request whose eligibility shows a reason — a non-cancelled work order already exists this season, a contract covers the service, the owner is on credit hold or do-not-schedule, or the property is marked no-services. Use Mark Already Covered or Reject.
  • Do not expect an email to go to the customer on approval or rejection. None is sent. If the customer needs an answer, the office calls or emails them.
  • Do not approve a general inquiry (contact form) as if it were a service request. It has no service, so the conversion fails; create the work order or estimate the ordinary way and reject the request with the reason.

Overview

1. QueueOffice ▸ Service Requests, filtered to New + Needs Review.
2. CheckMatched property, eligibility, review flags, what was asked.
3. FixCreate Customer & Property, or attach the property, when needed.
4. DecideApprove & Create WO · Already Covered · Duplicate · Reject.
5. ConfirmRequest shows Converted with the work order linked.

Pre-Checks

  • The queue is filtered to New and Needs Review (the default when you open it).
  • For the request in hand: you know the property, the service and the season it is for.

Steps

1Open the queueOffice
  • Office ▸ Service Requests (/admin/office/service-requests). Each request is a card: name, status badge, reference (W-…, F-…), submitted date, campaign, phone, email, address, matched property, work order link, interest tags, review flags and an Actions menu.
  • Filters: Type, Status, Service year, Source, Campaign, "Review flag contains". Tabs: Queue, Report, Campaign QRs.
2Read the cardOffice
  • Matched property: present means BOS found exactly one property. Needs Review means none, more than one, or the request was not eligible — the candidates are shown to the office.
  • Status set at intake: New (matched and eligible) · Already Covered (a work order or contract already covers it, linked on the card) · Duplicate (another request is active) · Needs Review.
  • Review flags are warnings, not blocks: contract_completed_for_year, standing_flag_no_contract, supply_mismatch, snow_contract_requested, zip_out_of_area. Check each before deciding.
  • Fall cleanup requests may have created a linked winterizing request (Needs Review) and, if the customer ticked a spring project, an estimate and a contact — look for those on the card.
3Fix the match when neededOffice
  • No property matched and the person is new: Actions ▸ Create Customer & Property. It creates the customer and fills in the property so Approve can finish. Check the address it built.
  • No property matched but they are an existing customer: open the request, attach the right property, save.
4ApproveOffice
  • Actions ▸ Approve & Create WO. The confirmation page repeats Submitted, Matched property, Current eligibility and Flags, and warns No property matched — assign one before converting when it cannot proceed.
  • Press Create Work Order. BOS re-checks eligibility, creates the work order (status Open) for the matched property and the request's service, copies the customer's notes and access notes into the work to do, attaches the current-year residential contract, adds a system note "Created from Service Request …", and sets the request to Converted with the work order linked — all in one transaction.
  • Success reads Work order N created and request marked Converted. Then schedule the work order as usual.
5Close without a jobOffice
  • Mark Already Covered — links the existing work order or contract when BOS can find it.
  • Mark Duplicate — when another request for the same thing is still active.
  • Reject — enter the Reason for rejection; it is saved to the office notes as "Rejected: …". Call or email the customer if they need to hear it; BOS does not.
6Win-back callsWin-back callers
  • The call list's Create WO button creates a winterizing request tagged with the reactivation campaign and converts it at once through the same conversion. Nothing further to do in the queue; the request appears there as Converted.

✕ Only the button links request and work order

A work order created from the property page for a request leaves the request open with no link. Four such requests had to be relinked by hand in September; one property with two possible work orders could not be, and had to be matched manually.

⚠ Eligibility is re-checked at the moment you approve

If a work order was created for that property in the meantime, or a contract now covers the service, the button refuses: "No longer eligible to convert… Use Mark Already Covered / Duplicate instead." That is the system catching a double job, not an error.

ℹ The season check looks at when a work order was created

A request can show "already covered" because of a work order created this season, even if that job has no scheduled date yet. Read the linked work order before deciding.

Quality Checks

  • Every converted request shows status Converted with a work order link on its card.
  • No request sits at New or Needs Review for more than a working day in season.
  • Every rejected request carries a reason in the office notes.
  • No work order for a web request exists without the request linked to it.

Completion

  • Approved: schedule the new work order; the request needs nothing more.
  • Covered / Duplicate / Rejected: the customer has been answered by phone or email where an answer was due.

Do / Don't

✕ Don't✓ Do
Create the WO from the property page because it is quickerApprove & Create WO — it is one click and it links everything
Approve past a review flag without reading itOpen the flagged item, then decide
Reject with "n/a" as the reasonWrite the reason the customer would recognise
Mark Converted by hand after making a WOBOS refuses; use the button, or ask admin to relink
